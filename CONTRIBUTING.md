# Contributing to Kioskium

Bug reports, device reports ("works / doesn't work on board X with compositor Y"), docs fixes and
code are all welcome. Open an issue first for anything bigger than a small fix. Security problems:
see [SECURITY.md](SECURITY.md), not a public issue.

## Setup

Nothing here needs a C++ compiler, a Qt SDK or Node: Qt, Chromium and Python come from the PySide6
wheels and are bundled by PyInstaller. You need Git and Python 3.10–3.14 (3.9 works with PySide6
6.8); the arm64 bundle also needs Docker.

```sh
git clone https://github.com/jerhemy/kioskium.git
cd kioskium
python -m venv .venv
# Windows:      .venv\Scripts\Activate.ps1   (if blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned)
# Linux/macOS:  source .venv/bin/activate
pip install -r requirements/windows.txt      # or requirements/linux.txt (exact versions CI uses)
pip install --no-deps -e .                   # editable install with the kiosk and kioskctl commands

python -m pytest                             # unit tests, a few seconds, no display needed
ruff check .
kiosk --windowed kioskium:test                # GPU, frame rate and kiosk checks
```

Useful while developing: `--windowed`, `--devtools` + F12, `--log-level debug`,
`--exit-after 10 --screenshot out.png`, `kioskium:input` (form fields and input events).

```
src/kioskium/
  cli.py        every command-line flag, config file loading, --name/{name} handling
  app.py        environment and Qt setup, second-launch hand-over, control server, main()
  browser.py    the window, pages, profile, kiosk policies, split screen, DevTools, fps overlay
  control.py    control API (HTTP/SSE), instance registry, weston.ini reader, the kioskctl client
  loading.py    loading / retry screen           screens.py   screen listing without WebEngine
  jsapi.py      window.kioskium (Qt WebChannel)
  pages.py      built-in pages (kioskium:test, kioskium:input, kioskium:idle); HTML in pages/
  policy.py     pure helpers (host allow-list, geometry)
  entry.py      process entry points (crash guard)
  assets/       window icon (generated by packaging/icons/make_icons.py)
tests/          pytest (no display / GPU needed)
examples/       kioskium.json, ControlClient.cs (.NET client), Postman collections
packaging/      pyinstaller/ (shared spec), windows/, linux/, linux-arm64/ (Docker), icons/
requirements/   pinned versions per platform
licenses/       third-party license texts shipped inside every bundle
```

## Building the bundles

Each build produces a one-folder bundle `kiosk/` with `kiosk[.exe]`, `kioskctl[.exe]` and the
Python runtime, Qt, Chromium and `licenses/` next to them. Ship the whole folder.

| Bundle | Command | Notes |
|---|---|---|
| Windows | `.\packaging\windows\build.ps1 -Clean` | `-Console` for a variant that logs to the terminal. *WinError 32* means a `kiosk.exe` from `dist\windows-x86_64\` is still running or the folder is open somewhere |
| Linux x86_64 | `bash packaging/linux/build.sh --clean` | needs glibc ≥ 2.39 on the target (PySide6 6.12 wheels) |
| Linux arm64 | `.\packaging\linux-arm64\build.ps1` (any OS with Docker) | `arm64v8/ubuntu:20.04` with Python 3.9 and PySide6 6.8.0.2, so it runs on glibc ≥ 2.31. Emulated on x86: 10–20 minutes per build; give Docker at least 8 GB. Output in `dist/linux-arm64/` |

The app icon is rendered from `docs/images/kioskium-icon.svg`: after changing the artwork, run
`python packaging/icons/make_icons.py` and commit the generated `.ico` and `.png`.

**Updating Qt / Chromium:** the PySide6 version decides both. Bump the `PySide6*` and `shiboken6`
pins in `requirements/windows.txt` and `requirements/linux.txt` (Dependabot opens these PRs), build,
and run `kiosk --version` and `kiosk kioskium:test`. If the build breaks or grows, check the module
lists in `packaging/pyinstaller/kioskium.spec` (`_DROP_MODULES`, `_KEEP_MODULES`, `_KEEP_QML`). The
arm64 pins stay at 6.8.0.2 until devices may require glibc ≥ 2.39.

## Making a change

1. Fork, branch from `main`, keep one topic per pull request.
2. Add or update tests in `tests/` for behaviour you change. Tests must not need a display or GPU.
3. Run `ruff check .` and `python -m pytest`.
4. Update the docs: user-facing flags in `README.md`, control-API changes in `docs/API.md`.
5. Keep the code running on **Python 3.9** (the arm64 build); ruff is configured for it.

## Commit messages and releases

Releases are automatic: [semantic-release](https://semantic-release.gitbook.io/) reads the commit
messages on `main`, picks the next [SemVer](https://semver.org/) version, tags it, creates the
[GitHub Release](https://github.com/jerhemy/kioskium/releases) (its notes are the changelog) and
attaches the Windows, Linux x86_64 and Linux arm64 bundles. Nothing is committed back to `main`. Pull requests are
squash-merged, so the **PR title** must follow this format too (CI checks it):

```
<type>(<optional scope>): <summary in the imperative>
```

| Type | Release | Use for |
|---|---|---|
| `feat` | minor (1.**2**.0) | a new flag, API endpoint, behaviour |
| `fix`, `perf` | patch (1.1.**1**) | a bug fix, a performance improvement |
| `docs`, `test`, `refactor`, `build`, `ci`, `chore`, `style` | none | everything else |
| any type with `!` (`feat!:`) or a `BREAKING CHANGE:` footer | major (**2**.0.0) | removed/renamed flags, changed API, changed defaults |

Examples: `feat(control): add /api/zoom`, `fix(split): keep the ratio after a resize`.

| Workflow | When | What |
|---|---|---|
| `pr-title.yml` | every pull request, and when its title is edited | PR title follows Conventional Commits |
| `ci.yml` | every pull request | ruff, tests on Linux and Windows, all three bundle builds with smoke tests |
| `release.yml` | every push to `main` | the same checks, then semantic-release: tag and GitHub Release (with release notes) with the bundles |
| `build.yml` | called by both; runnable by hand | builds, smoke-tests and uploads the bundles |

The version is never stored in the repository: [setuptools-scm](https://setuptools-scm.readthedocs.io/)
works it out from the git tags when the package is installed or a bundle is built, and writes it to
`src/kioskium/_version.py` (ignored by git). A build of a release tag reports `1.2.3`; a local build
after it reports e.g. `1.2.4.dev3+g1a2b3c4` (plus a date when there are uncommitted changes). Without
git history, e.g. from a source zip, it falls back to `0.0.0`. The repository needs *Settings → Actions → General → Workflow
permissions: Read and write* (to create the tag and the release). Preview the next version locally with
`npx -p semantic-release@24 -p conventional-changelog-conventionalcommits@8 semantic-release --dry-run --no-ci`.
